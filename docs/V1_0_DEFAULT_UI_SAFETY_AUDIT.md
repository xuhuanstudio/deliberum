# v1.0 Default UI Safety Audit

Date: 2026-06-16

This audit closes production readiness Gate 5 for the current v1.0 supported
Web scope. It verifies that normal default Web surfaces do not expose provider
secrets, provider values, raw JSON, env details, low-level ids, provider config
ids, or internal runtime language.

The audit did not reproduce a default-view data leak. One evidence gap was
found and fixed in this batch: `/runs` is a normal user route, but previous
browser smokes covered the same discussion catalog only through the landing
page. `smoke:web-boundaries` now opens `/runs` directly and applies the same
default-view safety scan.

## Gate 5 Scope

Gate 5 covers the default user-mode Web surfaces in the v1.0 supported path:

1. `/` landing and first-use entry;
2. `/setup/models`;
3. `/runs`;
4. `/runs/new`;
5. `/runs/:runId`;
6. `/runs/:runId/outcome`;
7. legacy `/sessions/:sessionId` user overview;
8. provider verification failure, rate-limit, and timeout recovery states;
9. continuation pause, setup-error, failed-stage, and retry recovery states.

The gate does not require developer-only panels to hide diagnostic data after a
user intentionally opens Advanced / Developer Mode. It also does not attempt to
classify every word generated by an external model as UI chrome. The relevant
claim is that Deliberum does not provide, render, or leak actual provider
secrets, provider values, env names, internal ids, raw JSON, provider config ids,
or daemon/runtime diagnostics in the default UI.

## Forbidden Default-View Classes

The current browser smokes scan default surfaces for:

- provider API keys and dummy or real release-smoke API key values;
- configured provider base URLs and model values;
- OpenAI, MCP, local preset, and timeout env var names;
- provider config ids such as `openai-main`;
- internal adapter ids and local preset object ids;
- run ids and session ids;
- ledger, event, projection, proposal, runtime, resource posture, and operation
  audit id language in user-mode surfaces;
- raw JSON labels;
- raw ledger entries and event type strings before Advanced is opened;
- raw stage metadata, stop reasons, provider safe-category codes, budget
  errors, registry errors, and stack text.

## Browser Evidence

Commands run on 2026-06-16:

```bash
corepack pnpm smoke:web-entry
corepack pnpm smoke:web-boundaries
corepack pnpm smoke:web-product-loop
corepack pnpm smoke:web-resilience
```

Results:

- `smoke:web-entry`: passed.
- `smoke:web-boundaries`: passed.
- `smoke:web-product-loop`: passed.
- `smoke:web-resilience`: passed.

Coverage:

- `smoke:web-entry` covers the connected landing page on desktop and mobile,
  plus unavailable local-service entry and `/setup/models` recovery guidance.
- `smoke:web-boundaries` covers the landing page with an existing discussion,
  the `/runs` discussion list, legacy `/sessions/:sessionId` user overview, and
  verifies that raw session and ledger details appear only after Advanced or an
  explicit ledger-events route is opened.
- `smoke:web-product-loop` covers Setup / Models provider setup, provider
  verification, focused and broader model-backed start links, `/runs/new`,
  Discussion Room before and after continuation, transient pause recovery, and
  `/runs/:runId/outcome`.
- `smoke:web-resilience` covers paused continuation, retryable setup error,
  failed-stage recovery, rate-limited provider verification recovery, and
  timed-out provider verification recovery.

## Real Provider Evidence

`smoke:web-release-readiness` is opt-in because it requires a real provider
secret and quota. The latest Gate 3 real-provider stability evidence used that
smoke to scan the real provider setup, start, room, retry, and outcome path for
provider secrets, provider values, env var names, provider config ids, and
low-level ids. The audit intentionally records only safe pass/fail evidence, not
the provider key, base URL, model, raw provider responses, or provider output.

## Gate 5 Result

Gate 5 is complete for the current v1.0 supported default Web scope.

Future default routes, start modes, recovery states, outcome surfaces, model
setup surfaces, or participant-management surfaces must extend the same
default-view safety scans before they can be considered release-ready.
