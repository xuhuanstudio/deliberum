# Quality Model

Deliberum is quality-centered. Quality is not decided by votes, identities, or one judge.

## Quality dimensions

- correctness;
- completeness;
- creativity;
- robustness;
- executability;
- explainability;
- traceability;
- uncertainty transparency.

## Quality Obligations

A Quality Obligation is a requirement a candidate must address. Obligations can be generated from:

- the Topic Contract;
- participant proposals;
- unresolved objections;
- evidence needs;
- final audit findings;
- domain-specific rules.

## Candidate comparison

A candidate should be evaluated by:

- which obligations it answers;
- which objections remain open;
- what evidence supports or weakens it;
- which assumptions it depends on;
- what trade-offs it makes;
- which target conditions it fits.

## No vote-based truth

Participant count can be an attention signal, but never a truth signal. Repeated reasons should be folded into one objection or support object.

## Audits

Deliberum should support:

- omission audit: detect dropped early insights or unprocessed objections;
- compression audit: detect final-summary loss or false certainty;
- centralization audit: detect over-dominance by a participant, projection, board, or context pack;
- final audit: verify that final outputs preserve unresolved boundaries.
