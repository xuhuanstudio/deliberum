# Governance

Deliberum is intended to become a global open-source infrastructure project. This governance document is intentionally lightweight at launch and should evolve as the community grows.

## Principles

- Project direction is quality-centered, not hype-centered.
- Architecture changes must preserve Topic Contract, Sealed Divergence, Candidate Frontier, Objection Ledger, Quality Obligations, Adaptive Deliberation, Evidence Check, Final Audit, and Outcome Compilation.
- No single maintainer, model, adapter, projection, or UI view should become an uncontested semantic center.
- Security and privacy concerns can block releases.

## Decision process

Large architectural changes should be proposed through design issues or pull requests. A proposal should include:

- the problem;
- the quality dimension improved;
- alternatives considered;
- semantic-center risk;
- security/privacy implications;
- migration impact.

## Maintainers

Initial maintainership is project-owner driven. A formal maintainer model can be introduced after the first public implementation stabilizes.

## Releases

Pre-1.0 releases may change protocol details. Breaking changes should be documented in release notes.
